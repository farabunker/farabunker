Here they are three named groups in a column that has room for them, and the row they came from is gone. THE GATES ARE THE MANAGE ROW'S GATES, MOVED AND NOT CHANGED. Nothing is newly exposed and nothing newly hidden: * Install guides is class P and renders for everybody -- it is the page a person needs BEFORE they can sign in to a box whose engines are not up. * Models and Library are class S: a member who clicked either would get a 403, and a nav entry that can only ever refuse is not navigation (ORCHESTRATOR RULING R1). `identity_is_admin` is True in the open posture -- everybody operates a household box -- so a household box gets all three SETUP entries. * ACCESS and BOX need accounts to exist as well as an administrator looking, so an open box is offered neither: there are no accounts to administer. Both groups sit behind ONE `{% templatetag openblock %} if {% templatetag closeblock %}`, which is also what keeps a group whose every entry is hidden from rendering an orphan label. SETUP cannot empty out, because Install guides has no gate. `foundation/settings_area.py` holds the SAME order, grouping and gates as Python, for `/settings/` to redirect by. Two readers, one truth: a context processor would have to run on every page in the box and cost a query the console's own query-count pin forbids, so the sidebar reads the two context keys the shell already has (`identity_is_admin`, `identity_posture`) and a drift test walks a really-rendered sidebar and asserts its first link is exactly where `/settings/` sends the same viewer.
