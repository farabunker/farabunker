How many chunks are retrieved for each question, 1–50. A larger value can surface more context but costs more of the chat model's context window (each chunk costs up to {{ chunk_tokens }} tokens) — a value too large for the currently-bound model's context window is rejected.

{% csrf_token %}

Raw cosine similarity (not a normalized 0–100% confidence) — 0 = off (keep every retrieved chunk). What counts as a useful value depends on which embedding model is bound to ingestion/retrieval; there's no universal threshold. Raising it drops weakly-matched chunks before an answer is generated; if every retrieved chunk falls below the floor, the question is answered with an honest "nothing matched" message and no citations, without calling the model.

{% csrf_token %}

Adds Postgres keyword matching (a tsvector column, English stemming, exact-token matching for other languages) alongside semantic search, concatenating and deduplicating both result sets — up to 2×top_k chunks, never a weighted blend of the two. Flipping this saves the setting immediately, but changes nothing about what's actually searched until you re-encode the index (Models → rag.embed → Re-encode), which rebuilds the chunk table and re-embeds every chunk in the library — this can take a long time. After the rebuild, the score floor is no longer applied.
