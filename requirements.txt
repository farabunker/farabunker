# Declared as first-party security dependencies 2026-09-10 (security
# audit round 3, B-7): both used to arrive only transitively (lxml via
# python-docx, defusedxml via openpyxl's own OPENPYXL_DEFUSEDXML default,
# itself pulled in transitively by something else entirely). Together
# they are what keeps `.docx`/`.xlsx` parsing from resolving a
# file-reading external entity (XXE) -- lxml's parser is built with
# resolve_entities=False, and openpyxl's worksheet reader refuses to
# parse at all once defusedxml sees a DTD entity declaration. A resolver
# that drops either transitive provider, or a pin back to a permissive
# XML parser, would silently reopen that hole with nothing to catch it.
# tools/rag/tests/test_readers_xxe.py is the negative test that backs
# this.
